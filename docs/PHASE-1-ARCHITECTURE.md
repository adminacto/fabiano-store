## 4. Модель данных

Полная схема — `prisma/schema.prisma` (39 моделей). Все сущности из ТЗ §12 присутствуют, плюс необходимые:

| Добавлено | Зачем |
|---|---|
| `UserRole`, `Session`, `PasswordResetToken` | RBAC many-to-many, серверные сессии, восстановление пароля |
| `*Translation` (Product, Category, Collection) | Контент на uz/ru/en без смешивания языков |
| `ProductCollection` | Товар в нескольких коллекциях |
| `SizeGuide` | Таблица размеров, общая для группы товаров |
| `OrderStatusHistory`, `AuditLog` | История изменений заказа, журнал действий админов |
| `PaymentMethodConfig`, `DeliveryMethod` | Настройки из админки (секреты — только env) |
| `HeroBanner`, `StaticPage` | Баннер и страницы футера управляются из Dashboard |

Ключевые решения:

- **Вариант = товар × цвет × размер** (`ProductVariant`, уникальный SKU). Размеры и цвета задаются для каждого товара отдельно — через набор его вариантов.
- **Галерея по цвету**: `ProductImage.colorId` → при выборе цвета показываются его фото.
- **Снимок заказа**: `OrderItem` хранит название, SKU, размер, цвет, цену, изображение; `Order` — адрес, контакты, способ доставки. FK на вариант `ON DELETE SET NULL`, поэтому история не ломается при удалении товара.
- **Деньги**: `Decimal(14,2)` + `currency`. Никаких float. Конвертация в тийины — только в адаптере Payme.
- **Целостность** (проверено на PostgreSQL 16, `tests/db/inventory.test.sql`): остаток ≥ 0, резерв ≤ остатка, `lineTotal = unitPrice × qty`, `grandTotal = subtotal − discount + shipping`, старая цена > цены, процент купона ≤ 100, рейтинг 1–5, телефон в E.164, один адрес по умолчанию.

## 5. Ключевые потоки

### Остатки (без overselling)

1. Добавление в корзину / изменение количества — проверка `quantity − reserved ≥ n` (мягкая, для UX).
2. Создание заказа — в одной транзакции для каждой позиции:
   `UPDATE "Inventory" SET reserved = reserved + n WHERE "variantId" = $1 AND quantity − reserved >= n`.
   0 затронутых строк → вся транзакция откатывается, покупатель видит, какой позиции не хватает. Конкурентные заказы не могут продать больше, чем есть: условие проверяется под блокировкой строки.
3. Оплата подтверждена (или заказ с оплатой при получении подтверждён админом) → `quantity −= n, reserved −= n`, `salesCount += n`.
4. Не оплачено до `reservationExpiresAt` (30 мин) или отмена → `reserved −= n`. Освобождение — фоновой задачей (cron route) с идемпотентной обработкой.

### Корзина гостя → пользователь

`Cart` в БД; гостю выдаётся подписанная httpOnly cookie с `cartId`. При входе позиции сливаются в корзину пользователя (количество суммируется и обрезается по доступному остатку), гостевая корзина удаляется. Цены всегда пересчитываются сервером — клиент никогда не передаёт цену.

### Оплата

Checkout → `Order(PENDING)` + `Payment(PENDING)` → redirect к провайдеру → **webhook** (проверка подписи: Payme — Basic Auth с ключом мерчанта, Click — MD5 sign_string; идемпотентность через `PaymentTransaction.idempotencyKey`) → `Payment.PAID` → `Order.CONFIRMED`. Страница возврата показывает «Проверяем оплату» и опрашивает наш backend, а не доверяет query-параметрам. Методы без credentials не показываются.

### Try-On

Кнопка «TRY IT ON LIVE» активна, только если `FEATURE_TRY_ON=true` + включено в настройках магазина + у товара `tryOnEnabled` + зарегистрирован движок SDK. Backend выдаёт короткоживущий токен сессии на каждого клиента (`/api/try-on/session`), а не один общий ключ. Изображения для примерки — `ProductImage.isTryOnAsset`.

## 6. Безопасность (план реализации)

| Требование | Реализация |
|---|---|
| Пароли | argon2id, минимум 8 символов, проверка по списку утечек — опционально |
| Сессии | httpOnly + Secure + SameSite=Lax, ротация при входе, отзыв всех сессий при смене пароля |
| RBAC | Разрешения в `Role.permissions`; guard в admin layout **и** в каждом admin handler |
| CSRF | SameSite cookie + проверка `Origin` у мутирующих запросов; Server Actions проверяют origin сами |
| SQL injection | Только Prisma / параметризованные `$queryRaw` с тегированными шаблонами |
| Rate limit | Вход, регистрация, сброс пароля, newsletter, промокоды, checkout |
| Загрузки | Проверка magic bytes (не только MIME), лимит размера, перекодирование через sharp (удаляет EXIF), случайные ключи |
| Webhooks | Проверка подписи, allowlist IP провайдера, идемпотентность |
| ПДн | Минимум полей, логи без телефонов/адресов, гостевой заказ доступен по токену из ссылки |

## 7. Дизайн-система (вход в PHASE 2)

- Палитра из ТЗ: `#F8F7F4` фон · `#171717` основной · `#77736E` вторичный · `#B59A78` акцент · `#E8E5DF` границы.
- Шрифты (обе гарнитуры поддерживают латиницу с узбекскими `oʻ gʻ` и кириллицу): заголовки — **Cormorant Garamond**, текст — **Manrope**, цены — Manrope с `tabular-nums`.
- Формат цены: `289 000 soʻm` (uz), `289 000 сум` (ru), `UZS 289,000` (en) — через `Intl.NumberFormat` + словарь названия валюты.
- Мобильная версия: фильтры — нижний sheet, sticky «Добавить в корзину» на странице товара, галерея со свайпом, checkout в один столбец с шагами.
